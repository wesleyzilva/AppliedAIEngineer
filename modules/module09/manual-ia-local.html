01 · Project charter

Purpose, outcome, and boundaries

Build and validate a personal AI assistant on the Windows laptop where it runs. For this first phase, Ollama and its models use their standard Windows installation and model store; the project, approved learning materials, and SQLite index remain in E:\wesleyzilva\repo\AppliedAIEngineer\modules\module09. The use cases are learning and work support across technical program management (TPM), full-stack development, and AI engineering.

Version 1 delivers local inference plus retrieval-augmented generation (RAG). Adding documents supplies external knowledge at query time; it does not train or modify Qwen’s model weights.

In scope for Phase 1

Install Ollama on Windows, run a local model, index authorized documents, inspect retrieved evidence, generate answers with source references, and validate the workflow on this laptop.

Deferred to later phases

USB portability and packaged runtimes, training a foundation model, fine-tuning, a remote service, multi-user access, image input in the assistant, and automatic execution of actions that modify data.

The current objective is local use on this Windows laptop, not a self-contained USB distribution. The standard Ollama installer changes this computer and stores models in the normal user model directory. We will plan a separate portability increment after the local workflow is proven.

03 · Solution architecture

What happens when you ask a question?

Each component has a distinct responsibility. This separation helps you identify whether a defect belongs to document preparation, retrieval, model inference, or response composition.

Your documentsAuthorized Markdown, text, and CSV files in data/docs/.
Python ingestionSplits content into chunks and requests embeddings from Ollama.
SQLite indexStores text chunks, source paths, titles, and serialized vectors.
RAG retrievalRanks candidate chunks against the user’s question.
Qwen responseReceives the question and selected context, then drafts an answer.

Stored on this laptop for Phase 1

Application code is in the repository; Ollama and models use their standard Windows installation and user model store; documents and the SQLite index stay in this module.

Executed locally

Ollama loads the model into system memory and computes embeddings and responses. Plan for CPU execution; do not assume the integrated GPU will accelerate inference.

07 · Implementation walkthrough

How the current RAG pipeline works

  1. Ingestion: the indexer discovers Markdown, text, and CSV files beneath data/docs/.
  2. Chunking: paragraphs are grouped into chunks of roughly 600 characters.
  3. Embedding: Ollama is asked to encode each chunk with nomic-embed-text.
  4. Persistence: SQLite stores source path, title, text, chunk position, and a serialized embedding.
  5. Retrieval: lexical term counts and cosine similarity are combined to rank candidate chunks; the highest-ranked results are returned.
  6. Generation: the assistant sends the question and selected context to Qwen, then returns an answer and source metadata.
Known implementation limitation: lexical matching carries substantial weight even though embeddings are stored. When Ollama is unavailable, the fallback embeddings are deterministic placeholders, not meaningful semantic vectors. Keyword search may still produce results, but this is not equivalent to genuine semantic retrieval. If Ollama is unavailable for generation, the application reports the failure rather than fabricating a model answer.
Choose context sources: in the chat, select one or more indexed files to restrict retrieval to those documents. With no files selected, retrieval searches the complete index. The CLI supports the same filter with repeatable --source options, for example python -m tpm_ai.cli agent "Refine meu resumo profissional" --source docs\perfil-profissional.md. Add or edit Markdown, text, or CSV files under data\docs\, then run python -m tpm_ai.cli ingest to refresh the index and source list.

RAG is not fine-tuning

RAG retrieves external text at query time. Fine-tuning changes model weights. This increment implements RAG; it does not train Qwen.

RAG does not guarantee truth

Evaluate source coverage, retrieval relevance, and questions with no supporting evidence. A model should acknowledge gaps instead of presenting unsupported claims as facts.

  2. Ingest it, then use ask with a question whose answer appears in that file.

09 · Configuration and observability lab

Learn model parameters and measure each call

The project uses Ollama's local API. A request has API-level fields such as model and thinking mode; the options object contains sampler and runtime parameters. There is no single option set guaranteed across every Ollama version, model, and runner; the catalog below separates documented common options from API fields not wired into this CLI. The CLI logs every embedding and generation request to data\logs\ollama-calls.jsonl. Logs are local, append-only JSON Lines and are excluded from Git. See the official Modelfile reference and Generate API reference.

Privacy: logs do not store prompt text, retrieved document contents, or generated answers. They do store model names, parameter values, character counts, timing, token counts, and status. Treat even this operational metadata as local project data.

Run a controlled experiment

Start from the Module 09 directory. Keep the question and retrieved context fixed, change one setting at a time, and record a quality score as well as latency. The second command changes only temperature:

Set-Location "E:\wesleyzilva\repo\AppliedAIEngineer\modules\module09"
$env:TPM_GENERATION_OPTIONS = (@{ temperature = 0.2; num_predict = 128; seed = 7 } | ConvertTo-Json -Compress)
python -m tpm_ai.cli agent "Quais são meus objetivos de aprendizagem?" --top-k 2 --model qwen3.5:4b
$env:TPM_GENERATION_OPTIONS = (@{ temperature = 0.7; num_predict = 128; seed = 7 } | ConvertTo-Json -Compress)
python -m tpm_ai.cli agent "Quais são meus objetivos de aprendizagem?" --top-k 2
Get-Content .\data\logs\ollama-calls.jsonl -Tail 10

The default generation options are temperature=0.2 and num_predict=128; JSON values override these defaults. On Windows PowerShell, set TPM_GENERATION_OPTIONS with ConvertTo-Json to preserve the JSON quotes when passing options to Python. Use --model to choose an installed chat model. Retrieval --top-k is separate from the sampler's top_k, so set top_k inside TPM_GENERATION_OPTIONS for token sampling.

Generation parameters you can experiment with

These are common Ollama Modelfile/runner options. Support and defaults can vary by Ollama version, model, and inference backend. Start with sampling and context controls; hardware/runtime switches can increase memory use or reduce performance.

num_predictMaximum tokens generated; -1 can mean unlimited.Try 64, 128, 256.Higher caps can increase latency. Current default: 128.
num_ctxContext window for input and output tokens.Compare 2048 and 4096 after checking model support.Larger context can consume more RAM/VRAM; it does not guarantee better retrieval.

Inspect the local call log

Each JSON line records a timestamp, operation, model, status, wall-clock duration, input lengths, selected options, and (when returned by Ollama) load/prompt/evaluation durations and token counts. The HTML dashboard loads the latest calls automatically when served through the local web command. Durations are shown in milliseconds, seconds, and minutes. Generation speed is approximately eval_count / (eval_duration / 1,000,000,000) tokens/second.

Automatic local log source

The dashboard reads the last 500 events from data\logs\ollama-calls.jsonl through the local web service. It refreshes every five seconds, including calls made from another PowerShell window. No file selection or upload is needed.

11 · Technical vocabulary

Glossary

LLMA large language model that generates text from input and context.
TokenA unit of text processed by a model; it may be a word, word fragment, or punctuation mark.
EmbeddingA numerical vector used to represent text for similarity comparison.
ChunkA portion of a source document that is indexed and retrieved as context.
RAGA pattern that retrieves relevant external content and supplies it to a model before generation.
SQLiteAn embedded, file-based database; this project uses it for the local index.
QuantizationA lower-precision representation of model weights that can reduce storage and memory requirements.
InferenceRunning a trained model to produce an output; distinct from updating its weights through training.
Acceptance criteriaObservable conditions that must be met before a deliverable is considered complete.
Risk / issue / dependencyA risk may occur; an issue is already occurring; a dependency is work or a condition required by another task.

  4. Improve chunking and ranking based on evaluation evidence, not anecdotal impressions.
  5. Consider a simple user interface or controlled read-only tools after the local workflow is reliable.
  6. Evaluate fine-tuning only if a measured behavior gap remains after prompt and RAG improvements.
The first meaningful project outcome is not “training an LLM.” It is asking a question, retrieving the correct passage from a local file, producing a verifiable answer with sources, and repeating the workflow with the network disconnected.
